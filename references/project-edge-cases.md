# Project-Specific Edge Cases

This file starts empty and grows as security-preflight is used. It captures things that are specific to *this user's* projects and stack - not generic vulnerability knowledge (that belongs in `vulnerability-checklist.md`, which already covers the textbook stuff). Organized by project so it stays useful across multiple codebases.

Each entry should explain *why* it's specific to this project, not just restate a finding, so it's actually useful the next time a similar feature comes up.

Format:

```
## <Project name>
- <short title>: <what's specific here, and how to handle it going forward>
```
